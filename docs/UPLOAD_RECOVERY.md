# 上传恢复与图超时保护

更新：2026-11-23；依赖061及此前迁移。

## 上传生命周期

`pending → registered` 表示上传目标已预登记，随后文件清单及任务成功原子提交。进程在Storage成功之后退出时，pending意图仍保存确切桶、owner和目标路径，后台无需遍历未知文件。

清理只领取超过宽限期、无有效租约且退避到期的pending/cleaning记录。先取得owner IO锁，再核验是否已有manifest：有manifest则修复为registered并跳过删除；否则发新token、删除确切对象并确认cleaned。失败保留记录，仅保存异常类别，首次退避120秒、封顶24小时。重复删除缺失对象可恢复丢失确认。

成功清理将没有任务的未完成材料标成failed，允许重新上传。registered意图保留至本人明确删除，用于归属和隐私清理；科目/材料删除后意图仍可保留路径，避免级联先丢失清理依据。产品隐私及科目删除也覆盖pending目标。

## 启用

默认关闭。部署环境设置 `UPLOAD_CLEANUP_ENABLED=true` 后，Beat每10分钟处理一批，最多50个候选；`UPLOAD_CLEANUP_GRACE_SECONDS` 默认3600，可设300–86400。自动历史数据清理仍使用独立的 `DATA_RETENTION_ENABLED` 开关。

运维预览可调用服务 `upload_cleanup_service.cleanup()`；执行必须明确传 `dry_run=False`，可通过user_id限定精确owner。此能力没有面向普通用户的全局清理接口。

部署先排空旧材料Worker、安装至061，再更新API/Worker和Beat；旧上传代码不会预登记意图，不能混跑。配置起点为根目录config.env.template，实际.env不进入版本控制。

## 图后台生命周期

索引入口使用owner IO锁。后台线程开始前固定待执行协程及截止时间；等待全局图锁超过期限时直接终止，不会在调用方返回后又开始索引。协作式异步IO通过wait_for取消。

对于无法立即取消的同步供应商调用，后台线程持有owner事务的引用；调用方超时返回不能关闭该连接。只有父调用和所有后台引用均结束才释放锁。于是产品删除、上传及附件清理在此期间保持409/busy/skip，直到后台停止。引用释放幂等，嵌套调用复用同一连接。

这会延长繁忙时间，也占用一个数据库连接；不声称已实现供应商强制取消或跨服务原子提交。连接/进程异常、多机故障、持续调度、P95和真实图质量继续保留专项。
